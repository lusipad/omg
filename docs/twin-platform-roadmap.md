## 从 `665f17c` 到 `eaddfa6`：已打通的物理底座与暴露的断点

构元最初的客户试点源码包把“指定 OpenModelica 版本的模型编译、仿真和数值回归”列为验收项，交付清单标记为 `blocked`，当时仓库中没有 `.mo`、`.mos` 或 `.fmu` 文件。VMS 2.0 建模规范定义了连续与代数方程、离散事件以及满足守恒关系的物理连接端口，浏览器主执行路径采用设备级数值内核；构元机械装配的位姿回放则采用 MuJoCo 正运动学。[构元客户工程验收要求](工程与验证边界.md#5-modelica-具名模型与客户工程验收) · [VMS 组件方程与守恒端口](D:/Repos/virtual-machine-studio/docs/spec-v2.0.md:1569) · [VMS 的后端选择记录](D:/Repos/virtual-machine-studio/docs/design/nonstandard-machine-platform-design.md:921)

从 `665f17c` 到 `eaddfa6` 的八次提交已经打通了“Modelica 具名模型 → Clang 18 编译浏览器 WebAssembly（SHA-256 摘要与模型版本双锁）→ OpenModelica 1.27.2 / Modelica Standard Library 4.0.0 原生 DASSL 复算对照”的底座，并完成了多级零件拆解：

- **理想丝杠与伺服整轴（`Gouyuan 1.0.0`）**：原稿设定的 `Modelica.Mechanics.Rotational.Components.IdealGearR2T` 基准已完成原生核验——120 rpm、100 N 轴向负载下，5 mm/rev 与 10 mm/rev 型号在 1 s 位移分别为 10 mm 与 20 mm，轴端驱动力矩分别为 0.0795775 N·m 与 0.159155 N·m，与解析期望一致；`Gouyuan.ServoAxis` 覆盖 11 个工况，8 s 全程浏览器 RK4 相对原生 DASSL 的最大角度误差为 0.001205°。[软件核验记录](验证记录.md) · [浏览器 WASM 加载校验](../src/lib/modelica-runtime.ts)
- **直线进给轴、零件级电机与三轴轮廓（`GouyuanLinear` / `GouyuanMotor` / `GouyuanContour 1.0.0`）**：支持从 BOM 选定丝杠导程和工作台质量求解进给与轴向推力（9 个工况最大位移差 0.0000134 mm），也支持将定子、转子和轴承装成伺服电机后装入 CNC 三轴复算 G2/G3 圆槽跟随误差（标准圆槽 5,236 个观测时刻与原生 DASSL 最大位置差小于 0.000017 mm）。[三轴圆槽复算](CNC三轴圆槽.md)
- **整厂调度与最小件追溯（`GouyuanFactory 1.0.0` + `composition`）**：支持多产线共享设备派工复算，并能从 8 台整机沿槽位逐层展开至 67 种、3,717 个最小件，子件修订额定值可直接参与下一轮求解。[多级部件拆解](设备分解.md)

以 Modelica 组件类、参数、连接器与方程作为物理模型库的表达基线已经可行。物理端口使用连接约束共同求解（如刚性连接转轴角度相等、力矩代数和为零），控制指令和测量信号保留明确输入输出方向。[Modelica 连接方程](https://specification.modelica.org/maint/3.6/connectors-and-connections.html)

但对照“陌生工程师拿外部资料自己搭机器”的目标，当前代码暴露出**三个必须收敛的结构性断点**：

1. **资料读取与参数提取仍绑死单一厂商和固定表头**。在线资料入口仅白名单放行汇川域名；配套伺服生成写死了 `SV660N Selection Chart` 的四行英文表头与 `MS1` 型号后缀规则；AI 提取虽具备严格的“原文逐行核对”防幻觉校验，但尚未读取模型库的参数定义，显式拦截了伺服类设备，且遇到选件歧义（如带/不带抱闸对应两个惯量值）时直接报错终止，无法保存“已核对字段 + 待确认缺项”。[在线资料限制](../api/twin-source.ts) · [汇川配套表硬编码](../api/servo-generation.ts) · [AI 草案校验](../api/twin-ai-router.ts)
2. **设备包与工作区按专题案例分叉，跨机理闭环无法连线**。`DevicePackage` 为不同场景叠加了顶层互斥字段（`ports/rules`、`servo`、`feed`、`factory`、`motorPhysics`、`axisPorts`、`contour`），`TwinWorkspace` 也禁止伺服或进给部件进入通用信号实例图，将信号接线、伺服轴、直线进给轴、三维机械安装点、工厂布局及 `so101`/`milo` 专项状态分隔在各自运行区。平台虽已分别具备 `GL10` 数字输入滤波、丝杠进给动力学和三维安装点，工程师却仍无法把它们连成“伺服推丝杠带动滑台 → 触发限位开关 → 经 DI 滤波请求控制器停机”的同一台机器。[设备包互斥分支](../contracts/twin-device.ts) · [工作区实例隔离](../contracts/twin-simulation.ts)
3. **模型清单分散、缺资料时难以分级降级，且初算选型端与孪生端割裂**。`public/modelica/` 下五份 `*-library.json` 各自描述局部参数，尚未统一声明参数量纲、连接端口与可回答的问题分级；缺少某项动力学参数时难以平滑退回几何行程或运动学试算；根路由客户项目的一阶初算及 MySQL 官方部件修订尚未与 `/twin` 设备库打通。[伺服模型清单](../public/modelica/library.json) · [进给模型清单](../public/modelica/linear-library.json) · [电机模型清单](../public/modelica/motor-library.json) · [初算规则](../contracts/engineering.ts) · [数据库部件表](../db/schema.ts)

AI 读取统一模型注册表的参数契约来匹配型号、提取参数并标出处。缺字段时保留已核实部分并生成待补项，未匹配到已有机理时登记建模需求。这个边界让工程师通过资料不断扩充跨品牌设备库，也让建模人员只在出现新物理机理或需要更高精度时扩充模型库。

### 工业标准与开源真机校准结论

在动工改造契约之前，核对了 2 套工业标准官方文件与 3 个 GitHub 开源真机工程仓库（`modelica/ssp-standard`、`admin-shell-io/submodel-templates`、`zmrdko/mesa_7i95t_config`、`gchesney/linuxcnc-asda-b3-e-configs`、`opulo-inc/lumenpnp`），并据此砍掉主观推测的多余中间层：

- **IDTA 02005-1-0（`Provision of Simulation Models`）**：严格区分 `Asset Type`（型号样本额定与默认组成）与 `Asset Instance`（装机换件、现场标定与安装极性）；单台设备可挂 `0..*` 个 `SimulationModel`，通信端口（区分 `input` / `output` / `acausal` 无因果物理连接与势/流变量前缀）归属具体模型而非写死在设备顶层，并登记 `SimPurpose`、`ScopeOfModel` 与固定步长/容差设定。
- **Modelica SSP 2.0.1（`.ssv` + `.ssm`）**：设备侧采用平铺参数表（值、单位、条件、原文定位/待确认候选），绑定侧采用 `{ source, target, factor?, offset? }` 线性映射，同量纲自动完成单位换算，不再自创嵌套 `paramMap` DSL。
- **LinuxCNC 台达真机配置与 `LumenPnP`**：`7i95t_xyz2.ini` 与 `02_io.hal` 验证了现场装机双驱反装极性（如 `Y1/Y2` 编码器缩放 `-10000 / +10000` 对应 `.ssm` `factor: -1`）、常闭（NC）接近开关极性取反（`-not` / `invert`）、单输出一对多扇出（同时连至限位与回零）以及 `10 ms` 周期滤波；`LumenPnP/openpnp/machine.xml` 验证了轴实例内嵌实测步进误差录波用于对照的做法。

## 资料不齐时怎样处理

每个参数字段均保存订货号条件、数值、原始单位与标准单位、适用工况、原始文档标题与版本/摘要、页码或表格行列定位，并显式区分其来源状态：`catalog`（手册核对值）、`measured`（实测标定值）、`derived`（程序换算值）、`assumed`（用户显式试算假设）或 `pending`（存在选件歧义或缺失待确认）。额定转矩与峰值转矩、连续电流与峰值电流分别保存。只有系列资料时引导用户选定或补齐具体订货号；公开网页被条款页、登录页或跨域策略拦截时，允许上传已取得的手册 PDF 并自动接回同一提取任务。

可用能力按工程问题分级启用，不做“缺一个动力学字段就全盘阻断”：

- 已知三维安装点、运动方向与行程上下限，即可先装配并校核几何位姿与极限位置；
- 补齐丝杠导程或减速比，即可计算角位移/转速与线位移/线速度的运动学传递关系；
- 补齐转子惯量、负载质量、额定/峰值电流与转矩后，方可解锁到位时间、制动推力与跟随误差动力学求解。

缺哪一项参数，界面直接指出它影响哪一级结论，允许补充原始资料，或以带警告标识的显式试算值先行推演。遇到模型注册表尚未覆盖的物理规律，保留已上传资料并生成结构化建模需求单。

## 四阶段实施顺序

1. **收敛统一模型注册表与通用设备包绑定契约**。在 `contracts/` 中建立统一的模型注册表 Schema，收拢 `public/modelica/` 下现有的五份模型清单（[library.json](../public/modelica/library.json)、[linear-library.json](../public/modelica/linear-library.json)、[motor-library.json](../public/modelica/motor-library.json)、[contour-library.json](../public/modelica/contour-library.json)、[factory-library.json](../public/modelica/factory-library.json)）与离散信号规则，明确每个模型版本的参数量纲、单位换算、守恒物理端口、有向信号端口及问题分级。在 [twin-device.ts](../contracts/twin-device.ts) 中引入通用 `modelBindings` 与字段级来源/待确认结构，通过兼容适配层承接既有 `servo`、`feed`、`motorPhysics`、`factory` 设备包，确保现有 70+ 测试文件与公开示例零回归。
2. **让跨品牌原始资料按模型定义进入设备库（以台达 ASDA-B3 为回归基准）**。将“资料获取归档”与“参数提取校验”解耦：升级 [twin-source.ts](../api/twin-source.ts) 与前端导入，校验真实文件头、识别 HTTP 200 条款拦截页、记录 PDF SHA-256 并按页缓存提取文本，支持在线受阻后拖入本地手册无缝续接；改造 [twin-ai-router.ts](../api/twin-ai-router.ts) 读取目标行为模型的参数契约，由 AI 输出候选数值、原始单位、选件前置条件、页码表头与原文摘录，由确定性代码逐行核对原文命中、执行量纲倍率换算、检查额定/峰值物理约束与配套电流匹配，并支持“已核实字段保留 + 选件歧义进入待确认卡片”。Pages 继续负责纯浏览器装配与仿真，在线抓取、PDF 转文字和可选 AI 提取复用本机或后端服务。[现有部署分工](../README.md)
3. **合流机电物理、离散信号与三维位姿，跑通一次有反馈的整机闭环**。解除 [twin-simulation.ts](../contracts/twin-simulation.ts) 对物理部件与信号部件的实例隔离，支持从 BOM、装配与接线描述生成带稳定 `instanceId` 的可编辑系统草稿（区分明确连接、推断候选与用户确认连接）。用位置指令驱动伺服，电机经丝杠带动滑台，滑台实时位移触发限位传感器，信号经 `GL10` 数字输入模块滤波后通知控制器停机。连续机电部分直接调用已验证的 Modelica WASM 内核，在通信步边界与离散信号/事件网络同步交换状态，生成唯一带时间戳的 `RuntimeTrace`，让三维位置、编码器曲线和限位/DI 跳变事件读取同一批样本，并逐步用适配器承接既有案例。
4. **接入实机测点对齐，并贯通早期选型端与孪生工作台**。型号包保存产品规格，工程实例保存装配与接线，实物资产保存序列号或资产号、测点通道映射及标定版本。先导入一段实机录波（如驱动器导出 CSV），对齐时间戳与单位，同工况比较位置、速度、限位触发与停机位置，再用另一段独立工况复验标定结果。同时打通根路由客户项目工作台（[engineering.ts](../contracts/engineering.ts)、[schema.ts](../db/schema.ts)）与 `/twin` 设备库，使早期一阶初算筛出的模块与官方部件修订可一键展开为动态仿真系统草稿。

### 首版具体要交付的接口

| 输入 → 输出 | 接口应完成的事 | 可独立检查的结果 |
| --- | --- | --- |
| 模型定义、求解内核与验证基准 → 注册表中的锁定版本 | 统一登记 `modelId@version`、参数量纲与倍率、物理连接器与信号端口、问题分级及原生回归记录，供设备包校验、AI 提取与运行时编排共用。 | 同一个已验证模型版本能通过通用 `modelBindings` 驱动两套不同品牌的参数配置；缺少某参数时准确返回受影响的问题级别、字段名与标准单位。 |
| 官网链接、BOM 料号或上传文件 → 一份可追溯的资料工件 | 识别系列页、具体型号页、条款拦截页与真实 PDF 文件头；记录来源 URL、版本、文件 SHA-256 和按页文本缓存；在线页面受阻时允许上传本地手册延续同一任务。 | 同一版 PDF（相同 SHA-256）只解析一次；HTTP 200 返回的使用条款 HTML 会被识别为拦截网页并提示上传手册，不会误当规格正文解析。 |
| 资料工件、目标型号、所需行为模型 → 字段候选、待确认项与设备包 | 向 AI 注入目标模型的参数契约；AI 给出字段值、选件条件、页码、表头行列与原始单位；确定性程序回读原文校验摘录存在性、归属、配套关系、物理上下限与单位换算，用户只处理歧义项与显式假设。 | 能从设备包中的任一参数跳回原资料页码与原文摘录；故意隐去区分抱闸选件的字符时，任务进入“待确认”并保留其余已核实字段，选定选件后即可完成安装。 |
| 设备实例、机械装配与信号接线、输入指令 → 单一 `RuntimeTrace` 运行记录 | 同时解析物理连接（电机—丝杠—负载）与信号连接（限位传感器—DI 滤波—控制器），在通信步协调 Modelica WASM 积分与离散事件求值。 | 同一时刻的三维滑台位置、编码器曲线和限位/DI 状态来自同一批样本；改变限位安装位置或 DI 滤波时间后，触发时刻、制动过程和最终停止位置随之改变。 |

工程运行时，每个部件实例拥有独立参数与运行状态。轴端转角、滑台位移和负载反力矩由已连接的物理方程共同确定，编码器、限位传感器、DI 模块和三维画面统一读取该次求解产生的 `RuntimeTrace`。

### 用台达资料验证哪些部分已经可行

开发基准选用样本中列举的驱动器 `ASD-B3-0421-L` 和电机 `ECM-B3M-CA0604RB1`。在本地直接请求台达全球站的英文目录地址时，HTTP 200 对应的正文是使用条款页。为核对参数，使用了 Gapp 公开分发、封底标明文件号 `DELTA_IA-ASDA_ASDA-B3_C_EN_20240703` 的台达原版 PDF（以下页码均为手册印刷页码）。[台达产品页](https://www.deltaww.com/en-US/products/Servo-Systems-AC-Servo-Motors-and-Drives/5158) · [厂商编制的 PDF 副本](https://www.gapp.co.uk/download/file/127/2460/deltaia-asdaasda-b3cen20240703-3pdf)

- 第 21 页核对驱动—电机配套行，第 31、37 页核对订货编码。电机编码中的 `R` 表示这一配置无抱闸、带油封。第 41 页的 400 W 列分别给出无抱闸和有抱闸转子惯量 `0.254`、`0.264`，表头倍率为 `10⁻⁴ kg·m²`，选定件换算后对应 `0.0000254 kg·m²`。第 32 页驱动器连续输出电流为 `2.65 Arms`，第 41 页电机额定电流为 `2.40 Arms`，两值分别进入各自设备包。
- 人工核对型号并指定表格位置后，程序从 PDF 文本读数、换算单位，调用现有设备包校验、组轴与伺服求解接口：在 90° 阶跃、折算负载惯量比 1 和当前控制增益下，名义模型按工作台判据在 433 ms 报告到位（油封摩擦降额与真机控制环整定仍需单独建模）。故意移除转子惯量时，设备包校验准确指出缺失字段。
- 这组核实过的数据直接作为第二阶段自动化测试的黄金对照答案：系统必须在**不编写任何台达专用表头解析代码**的前提下，依靠通用资料层 + 模型参数契约提取出上述带页码证据的字段，并在隐去 `R` 选件位时正确生成 `0.254` 与 `0.264`（×10⁻⁴ kg·m²）的待确认分支。新厂商盲测仍由未参与开发的人用另一套原始资料独立进行。

实施过程中，在 `docs/implementation-notes.md` 记录影响物理含义的设计决定、已知偏差、对应代码位置及验证证据。原始资料与自动推断有冲突时同时保留两者，继续完成可证实的部分；若需调整首个闭环用户工况或实机接入范围，再回到产品决策评审。

## 用陌生设备验收

首个整机闭环验收对象选定为一套**含伺服驱动与电机、滚珠丝杠滑台、限位传感器及数字输入模块的送料轴**。开发期使用的汇川与台达资料同正式验收资料严格分开：台达系列页与 PDF 用于打磨通用入库和歧义消解链路，正式验收由未参与开发的人另选支持机理内的第三家厂商或陌生型号进行。

| 验收项 | 可观察的结果 |
| --- | --- |
| 从零建模 | 只提供原始链接或手册 PDF、BOM、装配与接线资料及目标工况。工程师全程在界面内完成核对与选件确认，得到按型号分开的设备包及可复跑系统工程。如实记录总用时、人工补录项和开发介入次数（目标为零）。 |
| 换件与缺资料 | 更换配套电机或不同导程丝杠后重跑相同指令，变化趋势与幅值可用独立解析计算、OpenModelica 原生复算或实测解释；故意拿掉负载质量、惯量或选件字符时，系统准确列出受影响的问题级别、缺失字段和所需证据，不静默代填。 |
| 跨机型与闭环复用 | 在送料轴上改变限位开关安装位置或 DI 滤波时间，停机位置与事件时刻随之真实变化；将该送料轴封装为子系统装入另一台双轴或工位机器，仍保留其控制、反馈与限位行为。支持范围内新增厂商或型号所需的机型专页、写死型号的代码分支和厂商专用解析代码均为零。 |
| 实机对照 | 将真实驱动器/PLC 导出的指令与反馈映射到工程实例通道，按事先约定的工况、误差指标和容差对比到位时间、峰值速度与停机位置；尚未取得实测数据时，交付记录明确停留在离线仿真验收，不混同为实机通过。 |
