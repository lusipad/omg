# 从设备资料搭建仿真

在项目根目录运行 `npm ci` 和 `npm run dev`，打开 [设备仿真工作台](http://127.0.0.1:3000/twin)。开发模式下，本机设备库和仿真装配可以直接使用。已登录原平台的用户也可以从侧栏进入。

## 用汇川手册制作第一个设备

1. 在 **工程资源 → 创建设备** 中载入汇川资料，查看型号 **GL10-1600END**、手册修订 **A03** 和规格页定位。样例附带原文规格和中文说明，可以离线使用。实际制作时可读取汇川手册直链、上传可复制文字的 PDF，或粘贴其他厂商的规格表。系统会从清晰且唯一的标签预填相关身份字段。[汇川 GL10-1600END 官方手册](https://portal-file.inovance.com/owfile/ProdDoc/SC/19011103-SC/A03/19011103-SC_A03_GL10-1600END%20Digital%20Input%20Module%20User%20Guide-EN.pdf)
2. 生成草案。核对 16 路输入、导通条件 **> 15 V**、关断条件 **< 5 V** 和滤波时间 **10 ms**，再确认安装。设备包同时保存端口、行为规则、来源链接、页码或章节以及提取证据。同一设备包可以在装配中使用多次。
3. 选择已安装的型号并加入装配。在未接线的电压输入上设定 **24 V**，前进 **9 ms** 后数字输出仍为关，再前进 **1 ms** 后变为开。然后改为 **0 V**，再前进 **10 ms**，输出关断。
4. 想观察两个设备之间的信号，在 **示例库 → 信号接线** 打开已接好的虚拟电压源与第一路电压输入。可以直接步进试跑。点 **加入当前工程** 时，若现有接线需要替换，页面会请你确认。[打开信号接线示例](https://lusipad.com/omg/?view=workbench&example=wiring-demo)

也可以在 **工程资源 → 选择文件** 中直接选择从官方 PDF 生成并导出的设备包，检查相同的端口、规则及证据。[GL10-1600END A03 设备包](../examples/GL10-1600END-A03.device.json)

在线读取支持 `portal-file.inovance.com`、`www.inovance.com` 和 `www.inovance.eu` 的 HTTPS 资料。其他站点可使用文件或粘贴文字。URL 和 PDF 由运行工程的服务读取，PDF 转文字使用可执行文件 `pdftotext`（Poppler）。没有该命令时仍可用文本提取。扫描件需先取得 OCR 文字，系列手册宜选定单一型号的规格段落再生成。

## 添加自己的型号

对有明确通道数、导通与关断阈值、滤波时间的数字输入设备，可以使用同一提取器。对其他设备，可以编写设备包，或让 AI 按设备包格式整理资料。导入前会显示草案供核对。

一个设备类型由制造商、型号、修订号共同标识；每个实例独立维护输入和滤波状态。改变相同型号的行为后，请使用新的修订号，让旧工程仍可按原定义运行。[可直接导入的虚拟电压源设备包](../examples/voltage-source.device.json)

| 设备包字段 | 用途 |
| --- | --- |
| `schemaVersion` | 当前文件格式版本为 `1` |
| `manufacturer`、`model`、`revision` | 设备及模型修订的身份 |
| `source` | 保存 `title`、`url`、`locator`、`excerpt`，供核对原始资料 |
| `ports` | 每个端口定义 `id`、`label`、方向和类型，数值端口可标单位 |
| `rules` | 声明输入如何生成输出。包中仅接受引擎识别的操作 |

| 规则 | 计算含义 |
| --- | --- |
| `copy` | 将输入信号原样传到输出 |
| `linear` | 数值输出等于 `gain × 输入 + offset` |
| `digitalInput` | 电压严格超过 `onAbove` 或低于 `offBelow`，并持续达到 `filterMs` 后切换布尔输出 |

外部连线从输出接到同类型、同单位的输入。一个输入有一个驱动源；未接线时可手动给值。这个版本支持无环信号网络。对数字输入模型，初始输出为关，阈值未定义区间保持上一次确认的输出，未满足持续时间的脉冲会被滤除。这是本版离散模型对手册阈值与滤波时间的解释，真实模块的临界区特性需要台架测量。

## AI 辅助提取

在 **工程资源 → 创建设备** 的 AI 辅助入口可以复制带当前资料和格式约定的提示词，把外部模型生成的 JSON 作为设备包导入。资料不完整时，应保留缺项并补充手册。人工审核时应逐项对照摘录、单位和模型规则。

要启用页面内的模型调用，在服务端配置 `TWIN_AI_BASE_URL`（兼容端点的 API 根路径，如以 `/v1` 结尾）、`TWIN_AI_MODEL`，以及模型服务要求的 `TWIN_AI_API_KEY`，然后重启。该入口使用原平台的账号登录。用户主动发起后，服务端才会把当前填写的身份、资料定位和规格文字发送给配置的模型服务。返回值经校验后进入预览，确认安装后才进入设备库。

## 保存、交换与验证

工作台将设备库、实例、手动输入和接线保存在当前浏览器、当前网址下。设备包 JSON 用于分享一个型号；工程 JSON 包含完整装配，可以在另一浏览器导入。仿真时钟和滤波中的临时状态在重开或导入后从零开始。原客户项目的 MySQL 版本快照与此处的本机工程分别保存。

运行 `npm test` 检查资料提取、包校验、装配和步进结果，运行 `npm run check`、`npm run lint`、`npm run build` 检查类型、静态规则和构建。接线示例覆盖从资料生成到导出、还原、施加 24 V 再撤去信号的完整过程。

## 从离线模型走向现场孪生

同类设备可继续通过资料和设备包扩充。需要观察转动轴的位置和速度时，可在完整版的 **创建设备** 中从两条官网链接生成配套设备，再到 **装配与仿真** 运行位置阶跃。[汇川伺服轴示例](汇川伺服轴示例.md)

接入具体现场时，可把采集的时间戳、通道和物理单位映射到实例端口，比较同一段输入下的实测与仿真轨迹。当前交付覆盖离线信号仿真与刚性旋转轴响应，现场采集、对时和实机标定属于下一阶段。
