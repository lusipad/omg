# 客户试点指南

## 1. 试点目标

本阶段验证的是一套可落地的工程工作流：真实需求进入项目，整机由模块组成，参数与计算可追溯，部件有官方来源，方案变化形成版本，复核者能够重读并导出同一组证据。

试点成功不等于设备量产验证成功。现场机构、电气、控制和安全设计仍需独立工程流程。

## 2. 建议参与角色

- 客户工艺或设备负责人：确认节拍、负载、行程、空间、环境和验收指标。
- 机械工程师：确认载荷谱、结构、导向、传动、接口、强度、刚度与寿命。
- 电气工程师：确认电源、驱动器、电机、电缆、制动、接地和保护。
- 控制工程师：确认控制周期、轨迹、反馈、限位、报警和调试验证。
- 安全负责人：确认风险评估、安全功能、急停、防护和适用法规。
- 供应商或集成商：确认具体订货型号、样本版本、交期、接口和应用限制。

同一人可以兼任多个角色，但复核记录必须写明实际人员、时间和结论，不能用“系统通过”代替人工签字。

## 3. 试点输入清单

### 自动向导的最少输入

默认主流程是“选择设备 → 填少量整机需求 → 自动生成方案”。除项目名称、项目编号和现场说明外，三类设备分别需要：

- **三轴数控机床**：X／Y／Z 行程（mm）、移动质量（kg）、最高速度（mm/s）、加速度（m/s²）。
- **六轴机械臂**：末端负载（kg）、最大工作半径（mm）、最高关节速度（°/s）、关节加速度（°/s²）。
- **差速轮式平台**：整车质量（kg）、最高速度（m/s）、加速度（m/s²）、坡度（%）、轮径（mm）。

这些输入只用于生成可修改草案，不能代替完整载荷谱、结构接口、工艺力和现场验收数据。

### 整机与现场

- 设备用途、工艺流程、工作节拍和每日运行时间；
- 安装空间、姿态、环境温湿度、粉尘、液体、振动和防护要求；
- 供电、气源、通信、控制器、现场总线和既有系统接口；
- 适用法规、客户企业标准和验收流程。

### 直线进给轴

- 有效行程、定位与重复定位要求；
- 各轴实际移动质量、重心、外载荷、切削或工艺力；
- 速度、加速度、占空比和完整载荷谱；
- 丝杠导程、直径、支承、精度和预压候选；
- 导轨跨度、滑块数量、安装面和润滑条件。

### 旋转关节

- 各关节负载质量、质心半径、连杆与附加惯量和重力方向；
- 工作角度、角速度、角加速度、占空比和冲击工况；
- 减速比、刚度、回差、制动和失效姿态要求；
- 电机、减速器、轴承、法兰和电缆接口。

### 驱动轮

- 整车质量、驱动轮数量、轮径、轮宽和重心；
- 坡度、地面材质、滚阻、附着和越障条件；
- 速度、加速度、制动距离和驻坡要求；
- 电机、减速器、驱动器、电池和轮体轴承布置。

缺失数据应登记为“工程假设”或“待客户确认”，不能伪造成供应商数据。自动生成的原始需求、假设、警告和待确认项会保存在首版快照与审计信息中，并随 JSON 工程设计包导出。

## 4. 推荐试点步骤

1. 在首页点击“自动生成方案”，选择三轴数控机床、六轴机械臂或差速轮式平台。
2. 填写该类整机的最少需求，逐项检查数值和单位。
3. 在确认页展开查看自动分配假设、组成模块、初算状态和边界警告，再填写项目编号、名称与现场说明。
4. 确认生成。系统在同一事务中创建组成模块、计算运行与步骤、候选部件、审计事件和 V1 快照。
5. 进入工作台顶部的“方案待办”，分别处理阻断项、计算警告和待补部件；点击条目可进入对应模块。
6. 阅读每一步公式和代入值，把不适用于现场的自动假设改为有依据的项目输入。
7. 在“部件与来源”中核对首次自动候选的历史依据，并打开官方来源检查原文、样本版本和页码。
8. 对系列级资料补充具体型号；对旧样本索取现行数据表；没有有效候选的角色必须人工补齐，不能跨系列拼配后宣称选型完成。
9. 保存修改，确认新的计算历史和审计事件追加成功；后续编辑不会重写自动生成的 V1。
10. 在方案评审等节点冻结新版本，导出 JSON 设计包和 CSV BOM 供跨专业复核。
11. 将复核意见、供应商回复和实测数据纳入下一轮修改，对比版本并关闭问题项。

“高级模式”仍可用于手动组成和逐模块配置，但它不会自动分配整机需求。无论自动还是手动流程，当前都不会自动完成轴间或关节间载荷传递、完整运动学／动力学耦合、共享控制器和整机安全设计。左右轮仅在首次自动生成时共享整车需求，后续修改一侧不会自动同步另一侧。

## 5. 客户参考项目验收证据

至少保留以下材料，才能把“真实客户参考项目”从待完成改为通过：

- 客户需求基线和现场信息来源；
- 真实整机组成树及关键接口说明；
- 每个模块的输入、假设、计算结果和警告处置；
- 供应商具体型号确认和接口资料；
- 机械、电气、控制工程师的具名复核记录；
- 风险评估及安全设计引用；
- 必要的样机测试方案、原始测量数据和偏差分析；
- 客户试点结论、未关闭问题和后续责任边界。

平台中的模板项目、自动化临时项目和三维布局均不算现场验收项目。

## 6. 版本与变更管理

- 需求基线、方案评审、供应商确认、现场测试前分别冻结版本。
- 变更说明应写明原因、影响模块和需要重新验证的项目。
- 不直接覆盖历史计算；新的输入必须形成新计算运行。
- 规则版本或部件修订变化后，应重新计算受影响模块。
- 发现历史版本问题时，新建纠正版本，不篡改旧快照。

## 7. 数据库与部署演练

客户环境上线前至少完成：

- 数据库备份和隔离环境恢复；
- 迁移前备份、迁移评审和失败处置演练；
- 两个账号的项目隔离检查；
- OAuth 回调、退出登录和会话失效检查；
- 反向代理 HTTPS、安全请求头和日志保留检查；
- JSON 与 CSV 导出内容的敏感信息审查；
- 服务重启后的项目、计算、版本和审计重读检查。

## 8. 试点退出条件

只有全部适用项均有证据时，才建议进入下一阶段：

- 关键需求没有未登记假设；
- 阻断级计算警告全部关闭或有书面禁用结论；
- 具体订货型号和接口由供应商确认；
- 专业工程师复核完成，问题项有关闭记录；
- Modelica 如被纳入验收，已在指定 OpenModelica 版本实际编译并完成数值回归；
- 现场测试达到书面验收指标；
- 客户理解并签收剩余风险和不可直接制造的边界。
