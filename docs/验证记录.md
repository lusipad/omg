# pilot-0.2.0 验证记录

下列软件、数据库和客户项目浏览器检查记录于 2026-11-17。新增的 Modelica 单轴回归独立列出工具版本和适用范围。

## 软件检查

- `npm run lint`：通过。
- `npm run check`：TypeScript 全量检查通过。
- `npm run test`：Vitest 2 个测试文件、32 项测试全部通过，其中 23 项覆盖工程公式与边界，9 项覆盖整机自动分配与候选初筛。
- `npm run build`：前端与生产服务构建通过；三维场景保持独立按需加载 chunk。
- `npm audit --omit=dev`：0 个已知生产依赖漏洞。
- 完整 `npm audit` 仍报告 13 项（12 项 moderate、1 项 high），位于构建与开发工具链的依赖树；未使用破坏性强制修复，后续需专项升级和兼容回归。

构建工具仍会提示主前端 chunk 大于 500 kB，并提示第三方注释与压缩包体积警告。当前三维引擎已拆为独立 chunk，但主包继续分包仍属于后续性能优化项，不影响本次功能结论。

## 真实数据库闭环

`npm run test:persistence` 实际连接数据库并通过以下检查，临时账号和项目在测试结束后删除：

1. 三类模块定义已初始化；
2. 手动 CNC 模板生成三个真实组成模块；
3. 配置修改后保存并可重读；
4. 计算历史追加，步骤与输入摘要完整；
5. 非法部件角色和错误部件类别被 API 拒绝，且不追加历史；
6. 项目版本冻结并生成 SHA-256 内容摘要；
7. 工程包导出包含版本、计算和官方部件来源；
8. 自动整机需求在同一事务中创建模块、计算、来源候选、审计和 V1 快照，Z 轴姿态、候选角色与自动元数据均通过断言；
9. 另一账号读取项目被 `NOT_FOUND` 阻断。

部件种子实际执行 `npm run db:seed`，写入 3 个模块定义和 8 条官方来源部件修订。重复执行采用幂等更新，不覆盖后续人工或供应商确认状态。

桌面与移动浏览器实际执行并通过：

- 设备选择、整机需求填写、自动假设与警告确认、项目生成及工作台跳转；

临时视觉测试账号、项目、会话状态文件和截图已清理，不进入源码包。

将 `dist/` 与 `package.json` 复制到一个没有 `node_modules` 的独立目录后，使用受保护环境变量执行 `NODE_ENV=production node dist/boot.js`：

- 首页返回 HTTP 200，标题为“构元 · 通用模块工程平台”；
- 首页引用的生产 JS 资源返回 HTTP 200；
- 未登录 API 请求返回 HTTP 401；
- 验证后服务进程已停止。

这证明生产 bundle 可独立提供页面和 API，但不代表客户环境的 HTTPS、备份恢复或高可用部署已经验收。

## Gouyuan.ServoAxis 1.0.0 的软件核验（2026-11-19）

在 Ubuntu 24.04 amd64 使用 OpenModelica 1.27.2 和 Modelica Standard Library 4.0.0 运行原生 MOS。六个类通过 `checkModel`。原生构建生成伺服整轴、理想丝杠试验台和标准库永磁同步电机示例三个可执行模型。伺服整轴的检查返回 38 条方程、38 个变量，标准库 `SMPM_VoltageSource` 返回 775 条方程、775 个变量。[编译与模型检查脚本](../scripts/modelica/check-build.mos) · [公开模型源码](../public/modelica/Gouyuan.mo)

原生结果记录了 11 个伺服工况、3 个丝杠工况和 1 个标准库原始电机示例，共 15 项通过。报告保留了原版 ModelicaServices 未打 OpenModelica 专用补丁的兼容性提示，也记录了模型和构建日志的 SHA-256。[原生回归与编译器提示](../scripts/modelica/native-results.json)

原生 DASSL 在 100 ms 给出示例轴的位置与转速。90°、负载惯量比 1 时为 62.2403° 和 78.3803 rpm，−45°、相同惯量比时为 −31.1202° 和 −39.1902 rpm。两份设备包可从空白工程单独导入，导出再恢复仍选用 `v0.6-modelica.1` 修订及 1.0.0 模型版本。[工程与复算教程](Modelica伺服轴.md) · [工程导入回归](../tests/modelica-project.test.ts)

浏览器实际导出的 90° 响应 CSV 在 430 ms 结束，−45° 响应在 398 ms 结束，二者均满足到位判据。100 ms 位置、速度与上述原生值在所列小数位一致。网页使用由 OpenModelica 所生成方程编译的 WebAssembly，在新目录重新构建后，与随包发布的 WebAssembly 及清单逐字节相同。[浏览器工件及哈希](../public/modelica/runtime/manifest.json) · [100 ms 工作台截图](figures/modelica-servo-90deg-100ms.png)

发布的 WebAssembly 以 0.05 ms 步长执行 RK4。对照脚本对 11 个伺服工况各取完整 8 s 的 801 个样本，逐点比较角度、转速和转矩。相对原生 DASSL 的最大绝对误差分别为 0.001205°、0.005157 rpm、0.00000314 N·m，验收上限分别为 0.005°、0.02 rpm、0.00002 N·m。[逐点对照脚本](../scripts/modelica/compare-web.mjs)

另用 120 rpm、100 N 的无损丝杠试验台核对机械接口。导程 5 mm/rev 时，1 s 位移为 10 mm，轴转矩为 0.0795775 N·m，传递功率为 1 W。换为 10 mm/rev 时分别得到 20 mm、0.159155 N·m 和 2 W。标准库的永磁同步电机例保留其自身电机参数，用于核对标准库工具链。[原生回归结果](../scripts/modelica/native-results.json)

## GouyuanLinear.FeedAxis 1.0.0 的软件核验（2026-11-19）

进给轴复用同版本的驱动器、电机和丝杠，连接工作台质量后用 OpenModelica 1.27.2 原生 DASSL 运行 9 个工况。每组 801 个时刻均核对了工作台与转子间的力、转矩和功率平衡。浏览器对照同一源码的原生输出，六个通道均通过，最大位移差 0.0000134 mm，最大推力差 0.00177 N。[原生报告](../scripts/modelica/feed-native-results.json) · [浏览器工件清单](../public/modelica/runtime/feed-axis.json)

从空工程导入 BOM、设备包和装配关系，可重建示例。10 mm 指令下，5 mm/rev 丝杠和 5 kg 工作台在 100 ms 时移动 7.03659 mm，进给速度为 43.51835 mm/s，电机以 −0.01392 N·m 转矩制动，工作台推力为 −3.13501 N。换件和反向工况可在同一工作台复算并导出 CSV。[逐件装配与工况读数](Modelica直线进给轴.md)

## GouyuanFactory 1.0.0 的整厂软件核验（2026-11-19）

工厂设备的节拍由 OpenModelica 1.27.2 编译的模型方程计算。确定性的事件调度器由原生 Modelica 外部函数和浏览器 WebAssembly 共用。四个工况各放行 9 件工件、完成 33 道工序，逐项核对工位与载具编号，以及等待、取件、运输和完工时刻。每条产线的在制数量和每台资源的预占、作业区间均按相同事件表重建。[设备模型与接口](../public/modelica/GouyuanFactory/package.mo) · [整厂原生对照脚本](../scripts/modelica/verify-factory-export.py)

基准工厂整批耗时 324.50 s。只换较快移动机器人为 294.83 s，只更换 CNC-A 的加工模型为 256.22 s，只运行一台原型号 CNC-A 为 675.58 s。工厂布局、设备库和 BOM 可分别导入，从空工程重建。下载的 Modelica ZIP 可解压后运行 `omc run.mos`。[已执行的整厂复算记录](../scripts/modelica/factory-results.json) · [换型工况与重建步骤](Modelica工厂.md)
